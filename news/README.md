# news/ — the map-based news feed

What it is: the four Austin outlets' RSS feeds, refreshed daily, with each
story pinned on the news basemap when its text names a known
Austin place. Opens in the home page window under the **News Feed** chip.

Files
- `feed.geojson` — GENERATED daily by `.github/workflows/build-news-feed.yml`
  (never hand-edit). Each feature is one story; `geometry` is null when no
  place was found, and the page still lists those.
- `index.html` + `news.js` — the page. Map left, story list right (stacked
  on phones). Click a pin → its story lights up; click a story → the map
  flies there.
- `vendor/basemap.style.js` — the map's OWN style (`window.NEWS_BASEMAP_STYLE`).
  It began as a copy of the Moontower night cartography, minus the tour's
  towers/illumination/routes layers; it is the news map's to change now, and
  nothing on this page reads out of a `moontower` folder.
- `../tools/news/build-feed.js` — the builder (Node, no dependencies).
  `outlets.json` lists the feeds; `gazetteer.json` is the place lookup,
  generated by `build-gazetteer.js` from the austin.chat places plus
  `landmarks.json` (hand-kept names news uses, approximate points).

Run by hand
    node tools/news/build-feed.js
    node tools/news/build-gazetteer.js /mnt/c/Dev/projects/cityanatomyservices/austin-chat-archive/data

How a story gets placed: whole-word match of a gazetteer name in the
headline + summary, longest name first; short one-word names must be
capitalised. No language model, so every pin can be explained by pointing
at the word that caused it. Unmatched stories are not forced onto the map.

Known: Austin Monitor's RSS has been stale since 2025-11; it stays in
`outlets.json` and will fill in by itself if they fix it.
